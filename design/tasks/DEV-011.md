# Purpose

Deliver the deterministic measurement-window, aggregation, report, and export
capability required for M3 — AI Cost Control Baseline. The capability operates
over existing governed telemetry and bounded-execution evidence so a fixed
chat-heavy control window can be evaluated without inventing missing usage.

# Upstream intent

- `PROB-002`
- `FR-006`
- `FR-007`
- `NFR-002`

# Implementation boundary

DEV-011 is limited to:

- deterministic declaration of an M3 measurement window;
- deterministic aggregation, reporting, and export over existing governed
  telemetry and bounded-execution evidence;
- explicit baseline configuration for the chat-heavy control treatment;
- deterministic verification through `TEST-011`.

Each window declaration must explicitly supply every locked profile field and a
machine-readable half-open UTC evidence boundary (`start_inclusive`,
`end_exclusive`). Invocation evidence contributes only when it starts within
that interval and is terminal before its end. Outcome evidence contributes only
when finalized within the interval. Current-schema attempt membership is
derived from authoritative attempt identities linked to included invocations.
No locked value or boundary may be synthesized by a default.

DEV-011 does not authorize or include:

- telemetry, SQLite, or other data-model/schema modification;
- runtime-port, invocation, attempt, circuit, watchdog, continuation, or
  reliability-contract modification;
- architecture, NFR, security, external-contract, compliance, or migration
  change;
- automatic model selection or routing;
- M4 context optimization, Graphify implementation, treatment comparison, or
  ROI acceptance;
- any reset or reinterpretation of M2 attempt/circuit evidence.

The aggregation, reporting, and export source capability is implemented and
deterministically verified. The actual M3 measurement window has not started,
the M3 cost-control baseline remains not proven, and DEV-011 remains active
until governed delivery and acceptance closure.

# Locked M3 execution profile

```yaml
requested_model: gpt-5.6-sol
requested_reasoning_effort: medium
model_selection_strategy: fixed
routing_policy_version: null
context_strategy: chat-heavy
automatic_model_routing: false

```

The requested model and reasoning effort are control inputs. They remain
distinct from observed provider/runtime identity, which may be `unknown` when
the runtime does not affirmatively expose it. Context optimization is disabled
for this M3 control treatment.

# Measurement invariants

- Historical missing usage remains `unknown`, never zero.
- An unknown contribution makes its aggregate incomplete; exact known values
  remain visible only as known subtotals.
- An exact token KPI is decision-eligible only when every contributing accepted
  DEV has complete usage.
- Failed and rejected outcomes, failed attempts, retries, review, and
  orchestration usage remain visible and are not silently discarded.
- T0, T1, and T2 task/usage reporting remains distinguishable.
- File count is never used as a token or cost proxy.
- M3 remains incomplete and `cost_control_baseline` remains not proven until its
  roadmap exit criteria are satisfied with reproducible evidence.
