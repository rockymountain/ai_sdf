# Purpose

Implement FR-012 under accepted ADR-014, evidenced by CMP-005's canonical
projection boundary, and verify the result with TEST-020.

# Implemented scope

- add CMP-005 documenting the pre-existing but previously undocumented
  `constitution/agent-runtime.yaml -> tools/generate_agents.py -> AGENTS.md`
  projection architecture;
- add two role-conditioned prose invariants (correction/closure actor
  disposition duty; executor applicability duty) plus one independent-auditor
  reassessment invariant to
  `constitution/agent-runtime.yaml:runtime_projection.invariants`, using the
  existing flat-string list shape;
- regenerate `AGENTS.md` from canonical governance using the unmodified
  `tools/generate_agents.py`;
- add `knowledge/schemas/learning-disposition.schema.json` defining the
  prospective `learning_disposition: {value, rationale}` shape;
- add a corresponding shape-validating function
  (`validate_learning_disposition`) to `tools/traceability/validate.py`,
  deterministic and directly testable, intentionally not wired into the
  unconditional `main()`/`validate_traceability()` run against
  `control/project-control.yaml` (see ADR-014's verification scope boundary
  and the Owner-selected `MANUAL_PRESENCE_WITH_DETERMINISTIC_SHAPE`
  verification boundary);
- clarify `control/learning/README.md` minimally: a disposition is tracking,
  not an LSN or authority; `promoted_result` identifies the operative
  rule/control; the LSN lifecycle is unchanged;
- focused deterministic TEST-020 regressions.

# Semantic reconciliation against CMP-005

The implementation above was checked against CMP-005's boundary once that
boundary became explicit: `tools/generate_agents.py` was not modified;
`AGENTS.md` was not hand-edited, only regenerated by the unmodified
generator; role conditioning was added entirely as invariant text in
`constitution/agent-runtime.yaml`, not as generator logic; no generic agent
framework, policy engine, new runtime, provider adapter, automatic routing,
new implementation capability, Owner-authority transfer, or replacement of
`constitution/policies.yaml`/`constitution/quality-gates.yaml` was
introduced. No conflict, broader architecture, or new material scope was
found; the existing implementation conforms to CMP-005 as authored.
