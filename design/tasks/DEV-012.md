# Purpose

Provide a repeatable internal operator entry point for governed Codex execution
through the existing controlled runtime while ensuring every nonimplementation
invocation durably retains the exact structured human authorization that permitted
it. This enables later prospective M3 work to be metered instead of bypassing the
controlled runtime.

- `CMP-004`
- `ADR-007`

# T2 implementation boundary

The approved implementation is limited to:

- requiring canonical `HumanAuthorization` for every `acceptance_validation`,
  `review`, and `orchestration` invocation;
- atomically persisting invocation-linked `nonimplementation_authorized` evidence
  before runtime start using the existing `execution_evidence` table;
- adding a repeatable internal operator interface that explicitly supplies governed
  identity, treatment, purpose, and structured authorization inputs;
- composing existing scope, reservation, gateway, adapter, store, continuation,
  checkpoint, watchdog, and circuit behavior rather than duplicating it;
- deterministic verification under `TEST-012`;
- one separately authorized, pre-window controlled Codex adoption proof after the
  implementation and deterministic gates passed.

Schema version 3 remains unchanged. Historical authorization evidence is not
invented or backfilled. Continuation keeps its existing authorization and lineage
contract. Nonimplementation purposes remain read-only and create no attempt capacity.

# Exclusions

DEV-012 does not include or authorize:

- any further implementation attempt or operational DEV-outcome finalization for
  the accepted pre-window proof;
- an M3 measurement window or selection of DEV-012 as baseline filler;
- M4, Graphify, context optimization, or automatic model routing;
- automatic checkpoint closure after runtime success;
- changes to attempt counts, circuit states, watchdog semantics, continuation
  lineage, provider-adapter semantics, or exact/unknown usage handling;
- unrelated CLI or runtime refactoring.
