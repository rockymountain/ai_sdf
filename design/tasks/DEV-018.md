# Purpose

Restore conformance with accepted `FR-006` for the Claude controlled runtime. FR-006
requires every terminal record to include adapter/runtime versions. An independent
post-closure Codex audit of DEV-017 found that production Claude execution did not
satisfy this:

- `tools/ai_execution.py` constructed `ClaudeRuntimeAdapter` without a runtime
  version;
- `ClaudeRuntimeAdapter.runtime_version` therefore defaulted to null;
- the retained Claude PRE-WINDOW proof rows record `runtime_version = null`;
- deterministic operator verification explicitly accepted that null state.

Codex runtime-version capture was already conformant.

# Upstream intent

- `FR-006`
- `FR-007`
- `FR-011`

Existing design and decisions reused without change: `CMP-003`, `ADR-006`,
`ADR-012`. No new requirement, architecture, or decision is introduced.

# Post-closure correction

An independent Codex re-audit found that the first DEV-018 implementation resolved
Claude runtime version in `tools/ai_execution.py`, before
`ControlledInvocationGateway.invoke()`. For an `implementation` invocation with an
existing `RESERVED` candidate, a version-discovery failure at that point bypassed
`RuntimeStartControl`/start evidence entirely and stranded the reservation in
`RESERVED` instead of releasing it as a definite non-start, violating accepted FR-007
reservation semantics. The correction below moves discovery inside
`ClaudeRuntimeAdapter.start()`, reusing the adapter's existing pre-start
try/except and the gateway's existing terminal-failure handling, so FR-006 and FR-007
both hold together.

# Implementation boundary

DEV-018 is limited to:

- a Claude-local resolver in `src/ai_execution/claude_adapter.py` that runs the
  declared executable as `<executable> --version` (local executable inspection, not
  provider inference) and returns its single non-empty output line verbatim, without
  semantic-version parsing;
- calling that resolver from inside `ClaudeRuntimeAdapter.start()`'s existing try
  block, after governed invocation-start/reservation persistence has already
  occurred in the caller (`ControlledInvocationGateway.invoke()`) and before any
  Claude inference process exists;
- allowing that existing try/except to report exactly one
  `StartDisposition.not_started` through the existing `RuntimeStartControl` when
  discovery fails, so an implementation reservation releases
  (`RESERVED -> RELEASED`) through the existing gateway/controller machinery, no
  attempt is consumed, and the candidate slot remains reusable;
- accepting an optional non-blank `runtime_version` constructor override and an
  injectable `version_runner` on `ClaudeRuntimeAdapter`, for deterministic tests
  only; production leaves the override unset;
- passing an observed value through to the existing gateway/store path, which
  persists it in the existing `runtime_version` field;
- deterministic verification under `TEST-018`, including a real implementation-
  reservation regression proving the release/reusable-candidate behavior.

Provider-specific version discovery stays in the Claude adapter module. The generic
gateway, controller, store schema, policy, model, and `AIRuntimePort` are unchanged;
`tools/ai_execution.py` no longer performs any Claude-specific discovery itself.

# Exclusions

DEV-018 does not:

- rewrite, backfill, or reinterpret any existing telemetry; the retained Claude
  PRE-WINDOW rows with `runtime_version = null` remain immutable historical evidence;
- hard-code a Claude version, or derive one from an extension directory or path;
- change `AIRuntimePort`, the operational schema, capability profiles, routing, or
  Codex runtime-version behavior;
- add manual reservation-release logic to `tools/ai_execution.py` or otherwise
  mutate reservation state directly from the operator;
- introduce general runtime discovery or framework abstractions;
- perform a live Anthropic or OpenAI inference call;
- declare the M3 fixed set, start the M3 measurement window, or authorize M4.
