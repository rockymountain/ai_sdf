# Responsibility

CMP-003 is the Phase-1 bootstrap control boundary for bounded, measurable AI work:

```text
SDF workflow
  -> Execution Scope / Budget Guard
  -> ControlledAIInvocation Gateway
  -> AIRuntimePort
  -> replaceable runtime adapter
  -> opaque 0..N provider-internal requests
```

`ControlledAIInvocation` is one SDF-authorized execution unit exposed by an AI
runtime adapter. The hard enforcement point is immediately before `AIRuntimePort`
starts that invocation. The guard loads executable policy, validates
mandatory `dev_task`, `traceability_level`, `execution_scope_id`, `run_id`,
`invocation_id`, and `source_revision`, verifies that operational evidence can be
written, and establishes a finite watchdog. An implementation invocation also
atomically obtains `reservation_id` and `candidate_attempt_number`; review or
orchestration invocations may have neither reservation nor attempt identity. Only
then may the gateway call the port.

`execution_scope_id` is the stable governed execution-objective identity for every
purpose. It owns attempt budget when implementation applies; otherwise it provides
attribution, provenance, lifecycle, and circuit identity without creating capacity.

`source_revision` identifies the canonical Git base revision associated with the
objective/invocation. It is not a clean-tree assertion, partial-work detector, or
complete input snapshot. Continuation may retain it while resuming partial workspace
changes; CMP-003 does not add workspace fingerprinting or checkpoint replay.

The gateway also requires `invocation_purpose`: `implementation`, `continuation`,
`acceptance_validation`, `review`, or `orchestration`. Implementation reserves
capacity; continuation proves existing consumed-attempt lineage; the other purposes
may omit attempt identity. `acceptance_validation` is explicitly human-authorized,
performs no autonomous implementation work, and creates or replenishes no budget.
DEV-007's live tool-bearing proof uses this purpose.

An invocation without implementation-attempt identity cannot receive
repository/workspace implementation mutation capability. Mutation requires
`implementation` with reservation identity or P1-I16 `continuation` with existing
consumed-attempt lineage. The adapter may enforce non-mutation with a read-only
sandbox or equivalent capability restriction, but the canonical rule is
provider-neutral and cannot rely on purpose labeling alone.

Reservation and consumption are separate. Every reservation has a unique SDF-owned
`reservation_id` and `RESERVED` exclusively holds a `candidate_attempt_number`.
Affirmative evidence that the runtime or provider accepted execution moves it to
`CONSUMED` and binds `candidate_attempt_number` as `attempt_number`. Affirmative
evidence that execution definitely did not start moves it to `RELEASED`; insufficient
evidence for either moves it to `UNRESOLVED`. Consumed attempts are unique by
`execution_scope_id + attempt_number`. Each adapter's conformance specification maps
runtime evidence to these provider-neutral outcomes.

A proven local pre-start failure moves the reservation to `RELEASED` without
consuming budget. The durable reservation and failure evidence remain, while its
candidate slot becomes available. A later reservation may claim the same candidate
number with a new `reservation_id`. Uncertainty about runtime start moves the
reservation to `UNRESOLVED`, keeps the slot unavailable, and stops autonomy until
human resolution.

If evidence remains permanently insufficient, the reservation remains immutable and
`UNRESOLVED`, the old scope stays stopped, and no budget is released. Further work
requires a linked, human-authorized successor scope with predecessor, actor,
timestamp, reason, and disposition. An unlinked scope cannot bypass unresolved state.

Reservation state and consumed-attempt state are distinct. A consumed attempt is
`OPEN` until deterministic acceptance closes it as `PASSED` or `FAILED`. A governed
`usage_limit` interruption may move it to `SUSPENDED`; a human-authorized
continuation returns that same attempt to `OPEN` with a new `invocation_id` and
`resume_of_invocation_id`. Timeout, runtime failure, network error, cancellation,
and unknown terminal state are not automatically resumable and instead enter
`RECONCILIATION_REQUIRED` pending governed resolution.

Reconciliation has only three legal outcomes: affirmative
`terminal_status=interrupted` plus `terminal_reason=usage_limit` evidence permits
`SUSPENDED`; recovered deterministic checkpoint evidence determines `PASSED` or
`FAILED`; otherwise human disposition is recorded, the scope stays stopped, and
further work requires a successor scope. Resolution never manufactures checkpoint
evidence, frees consumed budget, or creates a retry.

For one scope, an active `RESERVED` reservation, an `UNRESOLVED` reservation, or an
unclosed consumed attempt blocks every new implementation reservation. A passed
attempt accepts the scope; only a failed attempt with remaining budget permits the
next reservation. This one-open-attempt rule survives restart and concurrent
processes.

The SDF-owned `AIRuntimePort` concept can start an authorized invocation, stream or
observe invocation evidence, and interrupt an active invocation. Every adapter must
conform to pre-invocation blocking, finite interruption, execution-identity
correlation, exact-or-explicitly-unknown usage, terminal-outcome mapping, and
non-bypass of SDF attempt/circuit governance.

# Runtime adapters

`CodexRuntimeAdapter` is the Phase-1 bootstrap adapter:

```text
runtime_session_id       <- Codex thread_id
runtime_invocation_id    <- Codex turn_id
start invocation         -> thread.turn(...)
stream evidence          -> TurnHandle.stream()
interrupt invocation     -> TurnHandle.interrupt()
current UsageEvidence    <- ThreadTokenUsage.last
cumulative reconciliation evidence
                          <- ThreadTokenUsage.total
```

Codex-specific SDK identities and types remain inside this mapping and its
acceptance tests. `invocation_id` remains the mandatory SDF-owned
controlled-invocation identity. `runtime_session_id`, `runtime_invocation_id`, and
`runtime_native_metadata` are optional evidence populated only when observed.
Adapters must not invent them. Their absence does not affect SDF attempt or circuit
correctness, and provider-native metadata is not core policy authority.

`ClaudeRuntimeAdapter` is the second controlled adapter. It uses Claude Code's
noninteractive stream-JSON CLI surface, explicit process interruption, and
purpose-governed capability arguments. Claude-specific process, permission, event,
and usage shapes remain inside the adapter. A local process-creation failure is
definite non-start; assistant or successful terminal machine evidence proves
accepted start; absence of either after process launch is uncertain. Exact usage is
recorded only when authoritative machine-readable provider components are sufficient
to determine canonical input and output counts without estimation. The adapter sums
Claude's emitted base input, cache-creation input, and cache-read input components as
canonical input; maps emitted output as canonical output; and derives canonical total
as input plus output. All four provider components must be present as non-negative
integers or usage remains unknown. Safe emitted usage key names and numeric values are
retained in provider-native metadata without prompt or response content. VS Code
extension/session state is operator context, not canonical SDF execution evidence.

The subprocess working directory is the governed repository; no Claude-specific
working-directory flag is required. Implementation uses supported `acceptEdits`
semantics: file edits and supported filesystem operations may proceed without
prompts, while other operations may remain denied or prompt-gated. Read-only uses
`plan`, restricts built-in tools to `Read`, `Glob`, and `Grep`, and supplies
`--strict-mcp-config` without an MCP configuration so user/project/local MCP sources
cannot provide an alternate action path. Runtime selection never adds unrestricted
permission bypass.

Trusted operator tooling selects `codex` or `claude` explicitly. Selection does not
change the gateway's capability decision, which remains derived from
`invocation_purpose` and governed attempt lineage. No automatic runtime routing,
agent-role registry, or coordinator is introduced.

# Operational state

Local SQLite at `.sdf/runtime/ai-execution.sqlite3` stores execution scopes,
reservations, consumed attempts, invocations, terminal evidence, usage aggregates,
and human-authorized continuation links.
The `.sdf/runtime/` tree is local operational state and must be excluded from Git.
Scope state and attempt reservations survive restart. The logical transactional
state machine preserves unique `reservation_id` values, one active candidate slot
and at most one open implementation attempt per scope, immutable released evidence,
and unique consumed
`execution_scope_id + attempt_number` pairs. The transition that records failure of
the final consumed allowed attempt also records `CIRCUIT_OPEN` atomically. CMP-003
does not prescribe a physical SQLite index or table layout.

Per-invocation `UsageEvidence` records `usage_status=exact|unknown` separately from
`terminal_status`. Attempt, DEV, and experiment/window aggregation records
`usage_completeness=complete|incomplete`; any unknown contribution makes the
aggregate incomplete while preserving known subtotals. Known subtotals are never
reported as exact totals.

Exact provider-neutral usage requires authoritative machine-readable components
sufficient to determine canonical `input_tokens` and `output_tokens` without
estimation. Canonical `total_tokens` is deterministically derived as canonical input
plus canonical output. Provider-specific normalization formulas remain inside
adapters, and missing required provider components remain unknown. The generic
`cached_input_tokens` breakdown represents provider-identified cache-read/hit input,
not cache creation; optional cached-input and reasoning-output absence is explicit,
never zero, and does not make otherwise exact core usage unknown. Codex may consume
its authoritative SDK aggregate when it is internally consistent. Requested
reasoning effort is capability-aware and never invented for an unsupported runtime.

Telemetry records `model_selection_strategy` using
`fixed|manual|risk_routed|other`, plus optional `routing_policy_version`. The version
is required when governed risk-routed or automatic routing is later active. These
fields support experiment comparability; Phase 1.0 does not enable automatic model
routing.

Telemetry records machine-readable `context_strategy` as `chat-heavy`,
`manual-context-pack`, `graphify-context-pack`, or `other`. This is measurement
metadata only; Phase 1.0 adds no Graphify, Context Pack routing, or automatic context
optimization.

Measurement windows bind an explicit treatment to each declared invocation purpose.
The treatment includes the authoritative adapter identifier plus the existing
requested-profile fields. Missing adapter identity, an undeclared purpose, or a
mismatch remains visible, retains cost, and blocks exact treatment-dependent KPI
eligibility. All controlled invocation usage still aggregates to the owning DEV,
with deterministic breakdowns by invocation purpose and runtime adapter. Purpose
treatments do not inherit implicitly.

Every watchdog timeout requests interruption through `AIRuntimePort`, records
`terminal_status=timeout` and terminal evidence, preserves exact observed usage or
records unknown usage, never zero, and requires human attention. A consumed attempt
enters `RECONCILIATION_REQUIRED`; a non-attempt invocation causes no attempt-state
transition or capacity creation and stops autonomous follow-on pending governed
disposition. Any later validation/review remains human-authorized and non-mutating.

Unknown usage normally stops autonomy. Human-authorized P1-I16 continuation is the
sole exception when affirmative terminal evidence proves
`terminal_status=interrupted` and `terminal_reason=usage_limit`. Prior unknown usage
remains unknown unless later recovered as exact machine-readable evidence; it is not
estimated or replaced by zero, and enclosing aggregates remain incomplete.

The finite watchdog mechanism and canonical fail-closed read of
`autonomous_execution.max_invocation_seconds` belong to DEV-007. Its schema requires
a positive integer, and a human-approved value must exist before the live
controlled-invocation acceptance test.
`constitution/policies.yaml` is the sole executable authority for the shared
`autonomous_execution` namespace. `max_attempts=2`, the attempt controller,
reservation and consumed-attempt lifecycles, one-open-attempt enforcement, circuit
breaker, and successor-scope anti-bypass behavior belong to DEV-008. DEV-007's live
tool-bearing test is explicitly human-authorized `acceptance_validation` and does not enable
autonomous multi-attempt retry. It uses a non-mutating capability profile, executes a
real command/tool item, and proves governed repository/workspace state was not
mutated. Its timeout case proves no fake consumed attempt or budget capacity is
created. Only DEV-008 may enable retry.

Before evidence collection, the store requires declared permissions, schema/version
handling, Git exclusion, a retention policy, and reproducible query or export for
experiment evidence. Remote or off-device backup is deferred unless later risk or
measurement-window durability demonstrates a need.

Phase-1.0 retains observations through the full declared measurement window and
until its experiment report is accepted and reproducibility is verified. Later
deletion requires a recorded measurement-window disposition; automatic time-based
deletion is outside Phase 1.0.

The operational store is observed runtime evidence, not canonical Git truth.
Canonical policy and design remain in `constitution/` and `design/`. Reports are
derived from retained telemetry and can be rebuilt. Raw prompt/response content is
outside the default accounting record.

After `CIRCUIT_OPEN`, the old scope remains closed. A human-authorized successor
scope records `predecessor_scope_id`, actor, timestamp, reason, and disposition;
old reservations, attempts, invocation evidence, and usage remain immutable. Phase
1.0 has no same-scope budget reset. This successor-scope rule is separate from a
human-authorized same-attempt continuation before deterministic closure.

# Boundaries

CMP-003 does not implement a universal provider router, Graphify, Context Pack,
multi-agent orchestration, or automatic model-tier selection. Graph/context treatment
and model/reasoning treatment are separate later experiments. Adding another runtime
requires an `AIRuntimePort` adapter and conformance tests, not changes to canonical
attempt, circuit, telemetry, or acceptance semantics.
