# Responsibility

`tools/traceability/validate.py` resolves each current T1/T2 task's declared
implementation paths against the post-change workspace after schema validation.
It obtains task identity, level, and lifecycle status from the canonical graph and
frontmatter registry. It reports the task ID and failing pattern on failure.

Literal entries are checked directly; glob entries use Python pathlib glob
semantics (`*`, `?`, character classes, and recursive `**`). Only existing files
whose resolved paths remain inside the repository qualify. Git metadata is not
implementation evidence. Git tracking is not required: new files must validate
before their first commit.

This component performs structural validation. DEV-003 extends it under ADR-003:
Git diff supplies changed paths, and the union of PR-declared tasks' implementation
paths must cover every non-excluded path. Only the base commit's canonical policy
can grant exempt/generated status. T2-triggered paths require a covering T2 task.
Each declared T1/T2 task retains its own commit marker, changed-path match, and
risk attestation. Human classification review remains mandatory where required.
