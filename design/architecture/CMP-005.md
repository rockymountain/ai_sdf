# Responsibility

`constitution/principles.yaml` is the canonical authority for the SDF
principles: their identifiers and statements. It is authored and owned
independently of `constitution/agent-runtime.yaml`.

`constitution/agent-runtime.yaml` is the canonical authority for the runtime
projection configuration it directly declares: the `runtime_projection`
block's `target`, `title`, `preamble`, a flat, role-conditionable list of
runtime invariants, the `before_change_read` path list, and the
`validation_command`. It does not itself contain or own the SDF principles it
causes to be rendered; those remain `constitution/principles.yaml`'s
authority.

`tools/generate_agents.py` is the existing deterministic rendering mechanism.
Its `render()` function reads both `constitution/principles.yaml` and
`constitution/agent-runtime.yaml` and combines their content into Markdown by
pure, order-preserving string formatting: each principle and each invariant
becomes one list entry, in declared order, with no filtering, reordering, or
role-specific branching in the generator itself. Role conditioning (for
example, invariant text beginning "When acting as implementation executor..."
or "When acting as independent auditor...") is expressed entirely in the
invariant text authored in `constitution/agent-runtime.yaml`, not in
generator logic.

In `--check` mode, the generator reads the current on-disk `AGENTS.md` in the
target repository as UTF-8 text (an empty string if the file does not exist),
computes the expected text by calling `render()` against the current
canonical inputs, and compares the two using Python string equality
(`actual != expected`). It does not read Git-committed history — it compares
against whatever is currently on disk, committed or not — and this is a
string comparison after UTF-8 decoding, not a raw byte-for-byte comparison,
though for well-formed UTF-8 text without encoding anomalies the two are
practically equivalent. It fails closed (prints an error and returns a
non-zero exit) on any mismatch. In write mode, the generator writes only
`AGENTS.md`; it installs nothing and mutates no other file.

`AGENTS.md` is generated, derived output. It is not authored directly; its
own preamble states "Generated from canonical governance. Do not edit
AGENTS.md by hand," and SDF-P-002 requires it be reproducible from canonical
artifacts and code. It carries no independent governance authority beyond
what its two canonical inputs (`constitution/principles.yaml` and
`constitution/agent-runtime.yaml`) and the generator's rendering logic
together produce; a change to projected content is made in those canonical
inputs and only then reflected here by regeneration.

# Authority flow

```text
constitution/principles.yaml    ─┐
                                  ├─> tools/generate_agents.py:render() ─> AGENTS.md
constitution/agent-runtime.yaml ─┘
```

Canonical truth precedes automation (SDF-P-001): `constitution/principles.yaml`
and `constitution/agent-runtime.yaml` are each authoritative for the content
they respectively declare, `tools/generate_agents.py` is a pure deterministic
transform over both, and `AGENTS.md` is evidence of that transform's output —
never a second source of truth.

# Component boundaries

This component is limited to instruction projection. It does not:

- introduce a generic agent framework, plugin system, or coordinator;
- introduce a generic policy engine or interpreter;
- add a new runtime, provider adapter, or automatic routing;
- grant new implementation/mutation capability to any role;
- transfer or redefine Project Owner authority;
- replace or duplicate `constitution/policies.yaml` or
  `constitution/quality-gates.yaml`;
- encode provider-specific governance semantics.

Role-conditioned obligations authored under this component (for example, an
accepted requirement/decision's executor, correction-actor, closure-actor, or
auditor duties) remain scoped to whatever their own accepted requirement or
decision defines. This component governs only how such text is canonically
sourced and projected, not its substantive content.
