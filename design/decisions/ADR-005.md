# Context and authorization

The user explicitly authorizes DEV-005 as the final Phase-0 environment hardening
change and classifies it T2. The old local/CI Python and PyYAML versions differ,
and transitive packages are unconstrained. No repository compatibility issue has
been identified with the locally successful Python 3.14.6.

# Decision

Use `.python-version` as the sole authoritative interpreter declaration, initially
3.14.6. CI uses setup-python's python-version-file input. A small standard-library
check verifies the selected interpreter before bootstrap and the isolated environment
after installation. Both paths use standard `python -m venv` and `python -m pip`.

Keep requirements-dev.txt as the sole validation dependency declaration. Pin
PyYAML 6.0.3 and jsonschema 4.25.1 plus their current runtime closure: attrs 26.1.0,
jsonschema-specifications 2025.9.1, referencing 0.37.0, rpds-py 2026.6.3.
No optional format extras or application dependencies are added. Require wheels
when installing, so the supported Windows setup does not need a native compiler.
Use pip --isolated to ignore user environment/config overrides and pip check to
validate dependency compatibility. Check installed versions and import locations
inside the venv. pip itself is supplied by the selected Python's venv bootstrap.

Exclude .venv from temporary test repository copies: it is an installed environment,
not source evidence. Existing test assertions and validator semantics are unchanged.

# Limits

This is package-version reproducibility, not an offline or bit-identical OS image.
Python/package distribution availability, OS-specific wheels, and Git installation
remain external prerequisites. Artifact hashes and a wheel mirror are not needed
for this Phase-0 contract. Historical TEST records retain the environments actually
used; only TEST-005 records the new environment. No constitution or gate changes.
