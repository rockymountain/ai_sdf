# Context

QG-006 is intentionally non-deterministic and merge-blocking. The human makes the
semantic-risk and level-classification decision; deterministic tooling may only
verify that authoritative evidence of that decision exists and applies to the exact
governed change. Current repository instructions state the human gate but do not
select or define its authoritative evidence source.

# Evidence-source options

## Repository-contained declaration or evidence

This option is portable, reviewable with the repository, and reproducible from Git.
By itself it does not prove reviewer identity or authority and can be self-authored
in the same change. It is acceptable only with a separate trusted authorization and
anti-self-approval mechanism.

## Trusted Git-host or PR approval evidence

This option can provide authenticated reviewer identity, disposition, and binding
to a PR or revision. It introduces external availability, event/API shape, branch-
protection, permission, replay, and provider/tool dependency concerns. Current
repository evidence does not establish that branch protection already satisfies
QG-006.

## Another governed trusted source

Another source is acceptable only when its identity, authority, revision binding,
disposition, audit retention, availability, and replay behavior are explicitly
governed and deterministically observable where required.

# Proposed invariant boundary

Any accepted source must establish:

- explicit reviewer identity and an authoritative reviewer-eligibility rule;
- binding to the exact revision or governed change;
- explicit approval or rejection disposition;
- staleness and replay resistance;
- accepted self-approval behavior;
- reproducible, auditable evidence retention;
- availability to deterministic presence/authority verification;
- provider/tool neutrality where feasible without weakening evidence.

Deterministic tooling must reject missing, stale, ambiguous, unauthorized, rejected,
or contract-invalid self-approval evidence. It must never make the semantic decision
or treat deterministic PASS as approval. Runtime `HumanAuthorization` remains a
different authority and evidence type unless a later accepted architecture proves
equivalence.

# Explicit owner decision still required

This proposed ADR does not select an evidence source. The Project Owner must choose
and accept one option, its authority model, and its self-approval rule before
DEV-016 can become implementation-ready. No Git-host/API integration is authorized
by this design package.
