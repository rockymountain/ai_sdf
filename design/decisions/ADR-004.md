# Selection and authorization

The user requested one executable policy family and explicitly retained human
accountability for material governance changes. The inventory and design were
reported before editing. This T2 change implements that authorized scope.
Trace-level evidence and provenance already consume policy; sensitive paths also
come from policy. PR marker/path obligations are the smallest independent family
whose existing canonical settings are ignored by the validator.

# Decision

Keep version 1 of quality-gates.yaml and QG-004's existing identity, deterministic,
and blocks_merge fields. Add scope.event=pull_request, scope.levels=[T1,T2], and
policy=implementation_evidence. Execute the three existing settings from
policies.yaml: t1_t2_require_commit_marker, commit_marker_format, and
t1_t2_require_changed_path_match. Keep their current names and values for continuity;
the gate's level list now determines applicability instead of the old key names.

The focused implementation-evidence-gate.schema.json validates this gate and policy
section, not every governance family. Missing fields/files, duplicate IDs or YAML
keys, unsupported shapes, wrong types, and marker formats without exactly one
DEV-n placeholder fail closed. Gate identity, event, deterministic execution, and
merge blocking remain the supported interpreter contract. Python supplies parsing,
Git/filesystem access, matching, rendering, and diagnostics, not policy defaults.

Static validation checks proposed configuration. PR validation loads the base gate,
policy, and schema through Git, validates proposed configuration, and enforces both
sets of obligations independently. A changed scope/false flag cannot waive the base
requirement; a marker-format transition must satisfy both formats during its PR.
Missing or disabled mandatory gate configuration is an error, not a skipped check.

# Bootstrap

Only immutable merged DEV-003 commit 972774f18b879d023eb005d1af021699ed6b4ed5 may
use the legacy QG-004 shape. Require its exact four-field gate, read its mandatory
policy flags/template, and map the old T1/T2 scope into the new representation.
Use the new schema for that one migration because the base predates it. Resolve
the Git ref to the full commit ID; no fallback based on missing fields or a mutable
branch name. Workspace and all other bases require the executable declaration.
Remove this compatibility adapter in a later governed change after transition PRs
no longer target the legacy baseline.

# Compatibility and remaining scope

Current settings preserve behavior. Artifact schemas, PR declarations, risk
attestations, DEV-002 path resolution, and DEV-003 provenance are unchanged. The
existing CI commands execute the new checks; step labels identify QG-004 evidence.
Other gates and governance hardcoding are explicitly deferred in
docs/phase0-policy-follow-up.md. Python/dependency alignment is follow-up debt,
not part of the QG-004 rule family. No production gate is relaxed in this change.

This protects against policy self-weakening, not malicious replacement of validator
or CI code. Code review and branch protection retain that separate responsibility.
