# Context

CMP-002 already validates artifact frontmatter against schemas and checks
traceability references, relationship types, task identity, and orphan tasks.
QG-001 and QG-002 declare those outcomes as deterministic merge blockers, but the
validator does not treat either declaration as an authoritative input.

Splitting the declarations into two implementation tasks would duplicate the same
gate-loading, validation, and self-protection work. Combining their semantic engines
would also be incorrect: artifact schema and reference integrity remain distinct
gates with distinct failure evidence.

# Decision

1. Keep QG-001 and QG-002 as separate canonical gate identities.
2. Deliver their authority binding as one bounded T2 increment because both
   substantive checks already exist in CMP-002 and share the same declaration-
   loading boundary.
3. Validate each declaration's identity, deterministic state, merge-blocking state,
   supported shape, and exact required presence.
4. Bind each valid declaration to its existing enforcement path. Do not create a
   second artifact-schema validator or reference-integrity validator.
5. Missing, malformed, disabled, duplicated, or unsupported declarations fail
   closed.
6. Apply the ADR-004 base/proposed self-protection pattern where a proposed change
   could otherwise disable the binding that governs it.
7. Keep artifact identity, schemas, relationship prefixes, reference existence,
   and orphan-task semantics unchanged.

# Constraints

This decision does not create a generic quality-gate or policy interpreter. It does
not alter QG-003 through QG-006 and does not remove the QG-004 compatibility adapter.
