# Intent

Every `ControlledAIInvocation` must pass through one SDF gateway that binds the
invocation to canonical change intent and records operational evidence before and
after the runtime adapter executes it. One SDF-authorized execution unit exposed by
an `AIRuntimePort` adapter is the Phase-1 accounting unit; opaque provider-internal
requests are not separate required accounting units.

# Acceptance

Before asking `AIRuntimePort` to start an invocation, the gateway requires
`dev_task`, `traceability_level`, `execution_scope_id`, `run_id`, SDF-owned
`invocation_id`, and `source_revision`. For an implementation invocation that
reserves attempt capacity, it also requires `reservation_id` and
`candidate_attempt_number`. Reservation alone does not create `attempt_number`;
only `RESERVED -> CONSUMED` binds `candidate_attempt_number` as `attempt_number`.
Review or orchestration invocations may have neither reservation nor attempt
identity when they do not belong to an implementation attempt. The gateway persists
an invocation-start record and finite watchdog before runtime start.

`execution_scope_id` is the stable governed execution-objective identity. It owns
attempt budget only when implementation attempts apply; non-implementation
invocations still use it for attribution, provenance, lifecycle, and circuit
enforcement without creating attempt capacity. `run_id` remains one workflow/process
execution instance and cannot reset scope budget.

`source_revision` identifies the canonical Git base revision associated with the
governed objective and invocation. It does not prove a clean working tree, absence
of partial edits, or a complete invocation-input snapshot. P1-I16 continuation may
retain it while resuming partial workspace changes. Phase 1.0 adds no workspace
fingerprint, checkpoint, or exact replay subsystem.

Every invocation declares `invocation_purpose` as `implementation`, `continuation`,
`acceptance_validation`, `review`, or `orchestration`. Implementation requires an
attempt reservation. Continuation requires an existing consumed attempt and P1-I16
lineage. `acceptance_validation` requires explicit human authorization, may omit all
attempt identity, performs no autonomous implementation work, and creates or
replenishes no attempt budget. DEV-007's live tool-bearing proof is
`acceptance_validation`. Purpose classification must not bypass attempt governance.
Any invocation that omits implementation-attempt identity must be denied
repository/workspace implementation mutation capability. Mutation requires either
`implementation` with reservation identity or `continuation` with existing consumed
attempt lineage. Adapters may enforce non-mutation through a read-only sandbox or an
equivalent provider-neutral capability restriction.

The adapter records `runtime_session_id`, `runtime_invocation_id`, and
`runtime_native_metadata` only as optional correlation evidence when the runtime
exposes them. Their absence is explicit, and the adapter must not invent identifiers
to satisfy telemetry. The terminal record includes adapter/runtime versions,
requested model and capability-aware reasoning effort, `model_selection_strategy`,
optional `routing_policy_version`, machine-readable `context_strategy`, timestamps,
`terminal_status`, optional `terminal_reason`, and SDF-owned `UsageEvidence`.
Terminal status is one of `success`, `failure`, `interrupted`, `timeout`,
`cancelled`, or `unknown`; it is separate from usage status. Exact usage records
the canonical core `input_tokens`, `output_tokens`, and `total_tokens`.
`cached_input_tokens` and `reasoning_output_tokens` are optional breakdowns recorded
when exposed. Their absence is unsupported/absent, never zero, and does not make an
otherwise exact core record unknown. Missing or unusable core usage is recorded as
`unknown`, never zero, and normally stops autonomous continuation. Requested
model identity is not treated as observed identity. Observed model and reroute fields
are populated only from affirmative runtime evidence. Runtime-native metadata is not
core policy authority. Raw prompts and responses are not retained solely for cost
accounting. Requested reasoning effort is recorded only when requested and supported;
it is never invented for runtimes without that capability.

`model_selection_strategy` is `fixed`, `manual`, `risk_routed`, or `other`.
`routing_policy_version` may be absent while routing is inactive and must identify
the governed policy if risk-routed or automatic routing is later enabled. Phase 1.0
records these fields for measurement readiness but does not enable automatic routing.

`context_strategy` is `chat-heavy`, `manual-context-pack`,
`graphify-context-pack`, or `other`. It is measurement metadata only; Phase 1.0 does
not implement Graphify, Context Pack routing, or automatic context optimization.

Attempt, DEV, and experiment/window aggregates record
`usage_completeness=complete|incomplete`. An aggregate is complete only when every
contributing invocation has exact usage. If any contribution is unknown, all known
values remain available as a known subtotal, completeness is `incomplete`, and the
subtotal must not be represented as an exact aggregate total.

Measurement coverage reports usage-complete accepted DEV divided by all accepted
DEV. Incomplete DEV or windows remain visible as operational evidence and must not
be excluded to manufacture an exact KPI. Exact token KPIs and treatment decisions
require complete usage for every contributing accepted DEV; otherwise report known
subtotals and incomplete coverage without claiming exact reduction. Statistical or
imputed treatment requires a separate governed decision, and zero is never imputed.

Telemetry for a governed continuation records a new `invocation_id`,
`resume_of_invocation_id`, the unchanged scope and consumed `attempt_number`, the
terminal reason, and human authorization. In Phase 1.0 the sole exception to the
normal unknown-usage stop is a human-authorized continuation when affirmative
terminal evidence proves `terminal_status=interrupted` and
`terminal_reason=usage_limit`. Prior unknown usage remains unknown unless later
machine-readable evidence is recovered; it is neither estimated nor replaced by
zero, and exact usage is not a continuation prerequisite. The same consumed attempt
continues, its usage is real cost, and its aggregates remain incomplete unless all
contributing invocation usage later becomes exact.

Every runtime adapter must prove pre-invocation blocking, finite interruption,
execution-identity correlation when runtime IDs are exposed, explicit absence when
they are not, exact-or-explicitly-unknown usage, terminal-outcome mapping, and
absence of an adapter bypass around attempt/circuit governance.

Every watchdog timeout requests interruption, persists `terminal_status=timeout` and
terminal evidence, preserves exact observed usage or records unknown usage, never
zero, and requires human attention. A timeout linked to a consumed attempt moves that
attempt to `RECONCILIATION_REQUIRED`. A timeout without a consumed attempt creates no
attempt-state transition or budget capacity and stops autonomous follow-on in the
scope pending governed disposition. Later non-mutating validation/review requires
explicit human authorization and cannot create implementation capacity.

`constitution/policies.yaml` is the sole executable authority for the
`autonomous_execution` namespace. DEV-007 owns the finite watchdog mechanism and
canonical fail-closed policy/read. A positive-integer, human-approved
`autonomous_execution.max_invocation_seconds` value is required before its live
controlled-invocation acceptance test.

For `CodexRuntimeAdapter`, one successful SDK turn containing a real command or tool
item must demonstrate that `ThreadTokenUsage.last` maps to complete current-
invocation `UsageEvidence` and `ThreadTokenUsage.total` is cumulative thread
reconciliation evidence. This DEV-007 `acceptance_validation` is explicitly
human-authorized, uses a non-mutating capability profile, and proves that the real
command/tool item did not mutate governed repository/workspace state. Its timeout
case must also prove that no fake consumed attempt or budget capacity is created.
