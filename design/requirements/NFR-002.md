# Requirement

The bounded execution runtime must fail closed, retain operational evidence across
process restart, and enforce the same scope budget under concurrent access. The
pre-invocation guard and local SQLite state transition must prevent duplicate
final-attempt reservation and every post-circuit controlled invocation. Reservation,
consumption, proven pre-start release, and insufficient-evidence unresolved transitions
must be durable and atomic. An unresolved reservation must remain unavailable and
stop autonomous continuation until human resolution.

Reservation classification is mutually exclusive: affirmative accepted-execution
evidence means `CONSUMED`, affirmative non-start evidence means `RELEASED`, and
insufficient evidence means `UNRESOLVED`. Adapter conformance specifications define
runtime-specific evidence mappings without changing these canonical outcomes.

Every reservation must retain a unique `reservation_id`. Released reservation and
failure evidence must remain immutable while the candidate slot becomes reusable by
a later reservation with a new `reservation_id`. Concurrent processes must not hold
the same active candidate slot, and consumed attempts must remain unique by
`execution_scope_id + attempt_number`.

At most one implementation attempt may be open for an `execution_scope_id`. An
active `RESERVED` reservation, an `UNRESOLVED` reservation, or a consumed attempt not
closed by deterministic acceptance blocks every new reservation for that scope.
This exclusion must survive restart and concurrent processes without depending on a
particular physical SQLite index design.

Canonical SDF execution policy, attempt accounting, circuit state, telemetry schema,
and acceptance logic must depend only on SDF-owned concepts and `AIRuntimePort`, not
on provider SDK domain types. A replacement runtime must require a new adapter and
conformance tests rather than changes to those canonical semantics. Phase 1.0 must
not introduce automatic provider routing.

Every controlled invocation must have a finite watchdog established before
`AIRuntimePort` starts it. Expiry requests interruption through the port, persists
timeout and terminal evidence, preserves exact usage already observed or records
usage as unknown, never zero, and requires human attention. For a consumed
implementation attempt, timeout enters `RECONCILIATION_REQUIRED`. Without a consumed
attempt, no attempt-state transition occurs, no capacity is invented, and autonomous
follow-on in the scope stops pending governed disposition. Later non-mutating
validation/review requires explicit human authorization and creates no implementation
capacity. No
timeout duration may be inferred or defaulted without an explicit governed value.
The canonical policy is `autonomous_execution.max_invocation_seconds` with a
required positive-integer schema. The watchdog mechanism and canonical fail-closed
policy/read must be delivered in DEV-007, with a human-approved value, before its
live controlled-invocation acceptance test.

`invocation_id`, `execution_scope_id`, and `run_id` are mandatory SDF identities.
Runtime session, runtime invocation, and native metadata are optional evidence.
Their absence must be explicit, must not affect attempt/circuit correctness, and
must never be replaced with invented identifiers.

`execution_scope_id` is the stable governed execution-objective identity. It owns
implementation-attempt budget when applicable; every non-implementation invocation
still uses it for attribution, provenance, lifecycle, and circuit enforcement.

`source_revision` identifies the canonical Git base revision for the governed
objective/invocation. It does not assert a clean tree, absence of partial edits, or a
complete input snapshot. Continuation may retain the same value across partial
workspace state; Phase 1.0 adds no workspace fingerprint, checkpoint, or replay
subsystem.

Every invocation has a governed `invocation_purpose`. Implementation requires
reservation; continuation requires existing consumed-attempt lineage;
human-authorized `acceptance_validation`, review, and orchestration may omit attempt
identity. These non-implementation purposes must not perform autonomous
implementation work or create or replenish budget. DEV-007's live proof is
`acceptance_validation`.

Any invocation that omits implementation-attempt identity must be denied
repository/workspace implementation mutation capability. Mutation requires purpose
`implementation` with reservation or `continuation` with consumed-attempt lineage.
Adapters may use a read-only sandbox or equivalent capability restriction, but the
canonical requirement is provider-neutral. DEV-007 must prove its human-authorized
tool-bearing acceptance validation did not mutate governed repository/workspace
state.

A consumed attempt may be suspended and continued only when the preceding
invocation has the governed resumable external reason `usage_limit`, the objective and scope
are unchanged, deterministic acceptance has not closed the attempt, predecessor
lineage is proven, and Phase-1.0 human authorization is recorded. The continuation
uses a new `invocation_id` and the same consumed `attempt_number`. Timeout, runtime
failure, network error, cancellation, and unknown terminal state are not
automatically resumable. Continuation must never replenish budget or permit work for
a third implementation attempt.

Reservation `UNRESOLVED` and consumed-attempt `RECONCILIATION_REQUIRED` are distinct:
the former means evidence establishes neither accepted execution nor definite
non-start, while the latter
concerns terminal evidence after consumption. `terminal_status` and
`usage_status=exact|unknown` are independent evidence fields.

An unresolved reservation may move only to `RELEASED` on affirmative non-start
evidence, to `CONSUMED` on affirmative accepted-execution evidence, or remain
`UNRESOLVED`. A reconciliation-required attempt may move to `SUSPENDED` only when
affirmative evidence proves `terminal_status=interrupted` and
`terminal_reason=usage_limit`, or to `PASSED|FAILED` only from recovered deterministic
checkpoint evidence. Otherwise it records human disposition, remains stopped, and
requires a successor scope. Human resolution cannot invent a checkpoint result,
free consumed budget, or create a retry.

If reservation evidence remains permanently insufficient, the old reservation stays
immutable and `UNRESOLVED`, the old scope stays stopped, and budget remains
unreleased. Further work requires a human-authorized successor scope with predecessor,
actor, timestamp, reason, and disposition. An unlinked new scope is prohibited.

Operational telemetry must minimize retained content, keep canonical policy/design
in Git, keep runtime observations outside canonical truth, and permit derived reports
to be rebuilt through reproducible query or export. Observations must be retained
through the complete declared measurement window and until the associated report is
accepted and reproducibility is verified; later deletion requires a recorded
disposition. Optimization must minimize AI resource cost per accepted DEV subject to
deterministic-quality, governance, security, acceptance-rate, bounded-retry, and
human-accountability constraints.

Per-invocation usage remains `exact|unknown`. Every attempt, DEV, and
experiment/window aggregate must expose `usage_completeness=complete|incomplete`.
Any unknown contribution makes the aggregate incomplete; known values remain a
subtotal and must not be presented as an exact total.

Exact provider-neutral `UsageEvidence` requires input, output, and total tokens.
Cached-input and reasoning-output tokens are optional breakdowns; unsupported
absence is explicit and never zero, and does not invalidate otherwise exact core
usage. Requested reasoning effort is recorded only for runtimes that support it.
Telemetry also records `model_selection_strategy` as
`fixed|manual|risk_routed|other` and optional `routing_policy_version`. The latter is
required to identify the governed policy when risk-routed or automatic routing is
later active. Phase 1.0 uses these fields for comparable measurement and does not
enable automatic model routing.
Telemetry also records machine-readable `context_strategy` as `chat-heavy`,
`manual-context-pack`, `graphify-context-pack`, or `other`. This is measurement
readiness only; Phase 1.0 does not implement Graphify, Context Pack routing, or
automatic context optimization.
Unknown usage normally stops autonomy. The sole exception is human-authorized P1-I16
continuation backed by affirmative `terminal_status=interrupted` and
`terminal_reason=usage_limit`; prior unknown usage remains unknown unless exact
machine-readable evidence is recovered, and aggregates remain incomplete meanwhile.
Coverage reports usage-complete accepted DEV over all accepted DEV. Incomplete DEV
or windows cannot be silently excluded from exact KPIs; exact treatment decisions
require every contributing accepted DEV to have complete usage. Imputation requires
separate governance and never imputes zero.
